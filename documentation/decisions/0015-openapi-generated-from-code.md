# 0015 — OpenAPI generated from annotated code, guarded by a parsed comparison

## Context

Hand-written OpenAPI files drifted from the services almost immediately: most responses had no schemas, new fields were never added, and nothing compared the two. ADR 0007 asked for drift to fail the build but there was nothing complete enough to check against.

## Decision

Each service's contract is generated by SmallRye OpenAPI from MicroProfile OpenAPI annotations on its resources (`@Operation` with a stable `operationId`, `@APIResponse` for success and error codes, `@Tag`) and from its typed DTO records. The generated document is committed as `documentation/api/<service>-openapi.yaml`. Every service has an `OpenApiContractTest` that fetches the running service's `/q/openapi`, parses it and the committed file, and fails on any difference or if the file is missing. `make openapi` regenerates the files (`-Dopenapi.update=true`); the diff is reviewed and committed in the same change as the code. Endpoints return typed records, never `Map`, so schemas stay accurate. The shared comparison lives in the `common-domain` test-jar.

## Consequences

An API change cannot be merged without its contract change showing up in the diff. The contract is per service; the single `documentation/api/openapi.yaml` named in ADR 0006/0007 and AGENTS.md is re-created as the merged, generated aggregate by T-0019, and the Dart client (T-0020) is generated from it. This guard checks the document against the code; checking real HTTP answers against the document is a separate step (T-0039). Operations that declare any `@APIResponse` must also declare their success response, because SmallRye stops adding the default one.

## Addendum (T-0019): the merged app contract

`documentation/api/openapi.yaml` is generated by merging the five per-service documents (`OpenApiAggregate` in the `common-domain` test-jar; `make openapi` runs it after the per-service generation). Operations tagged `internal` (service to service) or `meta` (`/v1/meta`, one per service) are not part of the app contract, and schemas only they used are dropped. The merge fails on a duplicate method and path, a duplicate operation id, or a schema name with two different definitions. `OpenApiAggregateTest` fails when the committed file differs from the merge. REST client interfaces are excluded from scanning (`mp.openapi.scan.exclude.classes`), otherwise a service documents paths it does not serve.
